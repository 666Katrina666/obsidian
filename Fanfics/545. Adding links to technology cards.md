## **C# (C Sharp)**

**Описание**: C# — это современный, объектно-ориентированный язык программирования, разработанный Microsoft. Он входит в экосистему .NET и является основным языком для разработки в среде Unity. C# сочетает в себе мощь и высокую производительность с читаемым синтаксисом, что делает его идеальным для создания игровой логики, инструментов и приложений разной сложности.

---

### **1. Ключевые особенности для Unity-разработки**
C# в Unity отличается от классического C# для десктопных или веб-приложений. Вот главные моменты, на которые обращают внимание на собеседованиях:

*   **Компонентно-ориентированная модель**: В Unity вы не пишете программы с точкой входа `Main()`. Вместо этого создаются **классы-компоненты** (наследующие от `MonoBehaviour`), которые "вешаются" на игровые объекты (GameObjects).
    *   **Пример**: `PlayerController`, `WeaponManager`, `UIWindow` — это всё компоненты.
*   **Жизненный цикл MonoBehaviour**: Понимание порядка вызова стандартных методов критически важно.
    *   `Awake()`: Вызывается один раз при создании объекта, **даже если компонент выключен**. Идеально для кэширования ссылок и инициализации.
    *   `Start()`: Вызывается один раз перед первым `Update()`, но **только если объект активен**. Используется для логики, которая зависит от других компонентов.
    *   `Update()` / `FixedUpdate()` / `LateUpdate()`: Основные игровые циклы. `FixedUpdate` связан с физикой (вызывается с фиксированным интервалом), `LateUpdate` вызывается после всех `Update` (полезно для камеры).
    *   `OnEnable()` / `OnDisable()`: Вызываются при активации/деактивации объекта или компонента.
*   **События (Events) и делегаты (Delegates)**: Основа коммуникации между объектами в Unity. Позволяют реализовывать слабую связанность.
    *   **`UnityEvent`**: Особый тип, который можно настраивать прямо в инспекторе Unity.
    *   **Делегаты (`Action`, `Func`)**: Стандартный механизм C# для реализации паттерна Наблюдатель.
*   **Корутины (Coroutines)**: Функции, которые могут приостанавливать своё выполнение (`yield return`) и возобновлять его позже. Используются для последовательностей, таймеров, асинхронных операций.
    *   **Ключевое слово**: `IEnumerator`. Пример: `yield return new WaitForSeconds(2f);`
*   **LINQ (Language Integrated Query)**: Мощный инструмент для работы с коллекциями. В геймдеве используется с осторожностью, так как может создавать аллокации памяти (`garbage collection`), что критично для производительности.
*   **Асинхронное программирование (`async/await`)**: Начиная с современных версий .NET и Unity, можно использовать для неблокирующих операций. Часто предпочтительнее корутин для сложных задач, но требует понимания контекста выполнения.

### **2. Типичные вопросы на собеседовании (и как на них отвечать)**

*   **Вопрос**: "В чём разница между `class` и `struct` в C# применительно к Unity?"
    *   **Ответ**: `Class` — ссылочный тип, размещается в управляемой куче, передаётся по ссылке. `Struct` — значимый тип, размещается в стеке (или внутри родительского объекта), передаётся по значению (копируется). В Unity `struct` используются для избегания аллокаций (например, `Vector3`, `RaycastHit`). Важно помнить, что большие `struct` копировать дорого.

*   **Вопрос**: "Что такое `garbage collection` (сборка мусора) и как её минимизировать в Unity?"
    *   **Ответ**: Это процесс автоматического освобождения памяти, занятой объектами, которые больше не используются. В Unity это может вызывать фризы. Для минимизации:
        1.  Избегать **аллокаций в цикле `Update`** (например, создание новых `List` или строк).
        2.  Использовать **пулы объектов (Object Pooling)** для часто создаваемых/уничтожаемых объектов (пули, враги).
        3.  Кэшировать ссылки на компоненты в `Awake()`.
        4.  Использовать `StringBuilder` для динамического формирования строк.
        5.  Осторожно использовать LINQ и боксинг (упаковку) значимых типов.

*   **Вопрос**: "Объясните разницу между `virtual` и `override` методами. Где это применяется?"
    *   **Ответ**: Ключевое слово `virtual` позволяет методу базового класса быть переопределённым в производном классе. Ключевое слово `override` используется в производном классе для изменения реализации виртуального метода. В Unity многие важные методы `MonoBehaviour` (`Update`, `Start`) не являются виртуальными, но этот механизм критичен для создания гибких иерархий игровых систем (например, базовый класс `Enemy` с виртуальным методом `Attack()`, который переопределяется в `RangedEnemy` и `MeleeEnemy`).

*   **Вопрос**: "Что такое `interface` и зачем он нужен? Приведите пример из игровой логики."
    *   **Ответ**: Интерфейс — это контракт, который определяет, *что* должен делать класс, но не *как*. Класс может реализовывать множество интерфейсов. Пример:
        ```csharp
        public interface IDamageable {
            void TakeDamage(int amount);
            int Health { get; }
        }
        ```
        Этот интерфейс могут реализовать и `Player`, и `Enemy`, и `DestructibleCrate`. Другая система (например, `Weapon`) может работать с `IDamageable`, не зная конкретного типа объекта.

*   **Вопрос**: "Как работает `null` в C# для Unity-объектов? Что такое `null` проверка с помощью `?` (null-conditional operator)?"
    *   **Ответ**: Для Unity-объектов (наследников `UnityEngine.Object`, например, `GameObject`, `Transform`) `null` проверка имеет особенность: после уничтожения объекта (`Destroy(gameObject)`) прямая ссылка на него не становится `null` в стандартном смысле C#, а становится "ложным null" (проверка `if(obj == null)` вернет `true`, но сам объект в памяти может быть не `null`). Оператор `?.` безопасно вызывает метод или получает свойство только если объект не `null`: `player?.TakeDamage(10);` Если `player` равен `null`, операция не выполнится, и исключение не возникнет.
