# Задача для облачной сессии: восстановить запросы на месте заглушек

Прочитай `CLAUDE.md` (правила хранилища), затем этот бриф целиком. Отчёт
на русском, коммиты на английском (Conventional Commits, без
`Co-Authored-By`).

## Цель

В заметках `Fanfics` 1702 заглушки: callout
`> [!question]- Запрос N` с телом `> (запрос не сохранился)`. Запрос автора
к ответу ниже был потерян при выгрузке. Нужно **восстановить запрос по
ответу**: написать, что автор, судя по ответу, попросила, и вписать текст
на место заглушки.

**Решение автора: восстановленный запрос никак не помечается.** Никаких
«(восстановлено)», «предположительно» и прочего — просто текст запроса,
как будто он был всегда.

Работа поделена на три части, у каждой своя облачная сессия и своя ветка.
Твоя часть — список файлов `Notes/restore_partK.txt` (K — из задания).

## Инструмент

`Scripts/tools/restore_prompts.py` (уже готов и проверен). Карта твоей
части — `Notes/restored_prompts/partK.json`:

```json
{"83. Under the Red Hood, Unmasked at Home.md": {
  "1": "помоги продумать фанфик: …",
  "2": "напиши кульминацию: …\n(без тяжёлой драмы)"
}}
```

Ключ — номер N из заголовка `Запрос N` (только у заглушек), значение —
текст; `\n` — перевод строки внутри callout. Порядок: дописал партию →
`python Scripts/tools/restore_prompts.py` (dry-run, 0 отказов) → `--apply`
→ коммит. Скрипт сам проверяет, что изменились только строки заглушек.
**Других файлов, кроме своих заметок и своей карты, не трогай** — так три
сессии не пересекутся.

## Как писать запрос

Пиши голосом автора. Её настоящие запросы (их в хранилище ~5800, смотри
соседние запросы в той же заметке — это лучший образец):

- «следующая глава: Готэм гудит о "ангеле спасающем людей". Джейсон у себя
  ворчит про всю ситуацию (но не может не помогать людям). Бэтсемья в пещере
  очарована "неизвестным новым героем" и хочет его завербовать (усыновить)»
- «длинная глава Джейсон просыпается. Семья чувствуя вину за недопонимание
  окружает его заботой (и из-за раны ему от нее не убежать).»
- «Напиши альтернативный план сюжета. Джейсон сбегает в момент падения
  Суда и просто приходит в поместье в костюме Когтя…»
- «милые сцены с привычками из приюта? простые фразы и просьбы на ручки.
  (юмор именно на милоту)»
- «следующая глава. Джейсон разбирается в том как это все работает.»
- «помоги продумать идею фанфика. …», «распиши план глав (много глав)»,
  «Напиши 3 главу», «перепиши.», «объясни связь с Нибелем»

Черты: часто со строчной буквы; без «пожалуйста» и вежливых оборотов;
пунктуация небрежная; пояснения и пожелания в скобках; имена из фандома
(Джейсон, Брюс, Дик, Бэтсемья, Красный Капюшон); тип запроса в начале
(«длинная глава», «следующая глава», «распиши план», «помоги продумать
идею», «напиши сцену»), потом суть. Шаблоны `Writing/Prompts.md` в
запросах не нужны: в хранилище они вырезаны, остаётся только описание.

**Что брать из ответа:**
- тип ответа определяет тип запроса: план → «распиши план глав …»; разбор
  идеи → «помоги продумать идею фанфика: <завязка>»; глава → «длинная
  глава <ключевые события>» или «следующая глава. <события>»; список идей →
  «напиши идеи …»; лор → «опиши лор …»; переписанная версия того же →
  «перепиши …»;
- в запрос — то, что ответ явно **выполняет**: завязка, кто участвует,
  ключевые события главы, точка зрения, если она объявлена, ограничения
  тона, если их видно. Обычно 1–4 предложения; для начальной идеи с
  большим сетапом — длиннее;
- **не пересказывай ответ и не раскрывай его находки:** запрос — то, что
  автор знала до ответа. Детали, которые модель явно придумала сама (имена
  второстепенных злодеев, лор, повороты в середине главы), в запрос не
  тащи;
- подсказки рядом: концовка прошлого ответа («Если хочешь, могу написать
  сцену, где…») — следующий запрос часто её и выбирает; описание заметки в
  шапке; соседние настоящие запросы задают стиль и сеттинг;
- перезапуск той же главы (тот же заголовок ещё раз) — запрос тот же или
  с правкой («перепиши. (меньше пафоса)»), если правку видно по разнице;
- первый запрос заметки должен давать сеттинг, остальные — как
  продолжение («следующая глава …»), если ответы идут подряд.

Не выдумывай того, чего в ответе нет. Если ответ — обрывок без начала и
восстановить запрос по нему невозможно, всё равно напиши самый короткий
честный запрос по тому, что видно («продолжи», «следующая глава»).

## Порядок

1. `git fetch origin && git checkout -b cloud/restore-partK origin/cloud/wrap-bare-prompts`.
2. Иди по `Notes/restore_partK.txt` сверху вниз, партиями по ~10 заметок.
   Для заметки: прочитай шапку и каждый ответ под заглушкой (начало,
   заголовки, концовку), соседние настоящие запросы — и пиши.
3. Партия: карта → dry-run (0 отказов) → `--apply` → коммит
   `content(vault): restore lost prompts in Fanfics <первая>–<последняя>`
   → `git push origin cloud/restore-partK`.
4. В конце: `restore_prompts.py` — 0 отказов, в твоих заметках не осталось
   строк `> (запрос не сохранился)`;
   `python Scripts/tools/bare_prompts/helpers.py verify ff02e1c~1` здесь
   **не годится** (запросы теперь другие), не запускай.
   Положи `Notes/restore_partK_report.md`: сколько заметок и запросов,
   5–10 примеров (заметка, запрос, начало ответа), места, где восстановить
   было трудно и почему. Закоммить и запушь. В `master` не мёржить.
