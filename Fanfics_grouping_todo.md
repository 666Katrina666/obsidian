# План группировки и разнесения вариаций фанфиков

Этот файл — рабочий список дел: идём сверху вниз. **Fanfics↔Fanfics** (этап 1) закрыт; текущий фокус — **Beta↔Fanfics** (черновики перед переносом в `Fanfics/`).

## Легенда типов

- `A` — параллельные версии: один сюжет/промпт, разный стиль или формулировки.
- `B` — развилка: до точки X похоже, после X разные ветки.
- `C` — один ствол + части: уже есть `N`, `N.1`, `N.2` и т.п.
- `D` — мета/лор: не отдельная версия фика, а общая справка или миростроение.
- `E` — слабое пересечение: только общий мотив, не факт что объединять.

## Правило разнесения (коротко)

- Для `A`: делаем один ствол `N` + версии `N.1`, `N.2`.
- Для `B`: фиксируем общий префикс в `N`, затем ветки `N.a`, `N.b` (или `N.1`, `N.2` с пометкой развилки).
- Для `C`: сохраняем иерархию, уточняем роль каждого файла (ствол/глава/альт).
- Для `D`: выносим общую информацию в один лор-файл, в сюжетах оставляем ссылки.
- Для `E`: ручная проверка перед любым объединением.

### Совпадение с уже существующим разветвлением (`N`, `N.1`, `N.2`…)

Если файл из отчёта совпадает с **уже оформленным семейством** (есть ствол `N` или ветки `N.k`), **не заводим для него отдельный номер-хаб** (как ошибочно сделали с `364` вместо `511`). Файл становится **ещё одной веткой** того же `N`: следующий свободный индекс (`N.3`, `N.4`…). Хаб и общее описание — у родительского `N`; в todo помечаем `C` + `A` (или только `A`, если это параллельные версии одной фазы). **Перед добавлением ветки** — проверить, не дубликат ли файл (см. ниже).

### Поиск и удаление дубликатов (не «версии», а копия)

1. **`Fanfics_variation_metrics.json`** — пары с **`jacc` ≥ 0.95** и **`seq` ≤ 0.05** (почти один текст, разный только заголовок/преамбула). Пример: `366`/`509.2` → jacc 0.985, seq 0.002.
2. **Сверка вручную** — от якоря (`напиши длинную главу:`, `**Глава.` …): если проза **байт-в-байт** совпадает, оставить **один** файл (обычно уже в правильном семействе `N.k`), второй **удалить**.
3. **Полные копии** — `Get-FileHash -Algorithm SHA256` по папке `Fanfics/` (или `fc /b`): одинаковый хеш → удалить один.
4. После удаления: убрать ветку из хаба, `Fanfics_variation_*`, `Fanfics_partial_overlap_report.md`, `Beta_vs_Fanfics_partial_report.md`; в todo — «было `X`, удалён как дубликат `Y`» (как с файлом `13`, `404`).

### Вариант «хаб» (когда не удаляем ни одну версию)

- Номер **`N`** — **меньший** из пары; файл **`N. … — обобщение.md`**: общее описание того, что есть в **обоих** текстах; в строке тегов — только **пересечение** тегов; блок **«Версии сюжета»** с wiki-ссылками — **в конце**, после общего описания.
- Имена версий: первый исходный файл → **`N.1`**, второй → **`N.2`**; при третьей линии — **`N.3`** и т.д.

### Правило для Beta (черновики)

1. **Beta не канон** — финальные версии живут в `Fanfics/` с хабами `N` и ветками `N.k`.
2. **Повтор с Fanfics** — сначала классификация (этап 1), перенос — только на этапе 2.
3. **Если хаб Fanfics уже есть** — Beta становится `N.k`, не отдельным номером.
4. **Дубликат прозы** — удалить Beta; дубликат только в Fanfics — удалить лишнюю ветку Fanfics.
5. Источник пар: [[Beta_vs_Fanfics_partial_report.md]] (+ ручные кластеры в этапе 1б).
